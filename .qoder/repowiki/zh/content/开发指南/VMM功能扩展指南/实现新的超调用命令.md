## 引言
本文档深入讲解如何在VMM（虚拟机监视器）中扩展超调用（Hypercall）接口，以支持自定义的主机-客户机通信功能。重点分析`hvc.rs`文件中的现有超调用机制，指导开发者如何安全、高效地添加新的超调用命令，并确保系统稳定性与安全性。

## HC编号分配机制与HyperCallId枚举扩展
超调用命令码由`axhvc`库中的`HyperCallCode`枚举定义，该枚举实现了`TryFrom<u32>`，用于将客户机传入的原始数值转换为合法的超调用类型。当接收到未知或无效的命令码时，构造函数会返回`InvalidInput`错误并记录警告。

要添加新的超调用命令，必须首先在`axhvc` crate 的 `HyperCallCode` 枚举中定义一个新的变体（例如 `HC_VM_GET_INFO`），并为其分配一个唯一的32位整数编码。此编码需避免与现有命令冲突，通常建议在开发阶段使用保留范围或动态分配策略。

## 主处理函数中添加匹配分支
所有超调用的分发和执行逻辑集中在`HyperCall::execute()`方法中，该方法通过`match`表达式对`self.code`进行模式匹配。开发者需要在此`match`块中为新添加的`HyperCallCode`变体增加一个新的分支。

每个分支负责处理特定命令的完整生命周期，包括参数解析、权限检查、核心逻辑执行以及结果写回。若未找到匹配项，最终的`_ =>`通配分支会捕获所有不支持的命令并返回`Unsupported`错误。

## 安全的参数提取与宿主操作执行
超调用的参数通过`args: [u64; 6]`数组从客户机vCPU寄存器传递。在新命令的处理分支中，应首先将这些`u64`值安全地转换为目标类型（如`usize`），然后根据语义解释其含义。

对于涉及内存操作的命令（如IVC通道建立），参数通常是指向客户机物理地址（GPA）的指针。必须使用`GuestPhysAddr::from_usize()`将其封装，并通过`vm.read_from_guest_of::<T>()`从客户机地址空间安全读取实际数据。任何对客户机内存的写回操作也必须通过`vm.write_to_guest_of()`完成，以确保地址转换和权限检查。

宿主操作的执行应调用VM对象提供的安全API，例如`vm.alloc_ivc_channel()`用于资源分配，`vm.map_region()`用于内存映射等。

## 上下文切换中的异常处理与原子性保障
超调用执行过程中可能因客户机提供无效地址、资源不足等原因失败。所有此类操作都应使用`?`运算符传播`AxResult`错误，确保异常能被正确处理并返回给客户机。

为了防止多vCPU并发调用导致状态不一致，所有共享状态的修改必须是原子的。本项目通过`static IVC_CHANNELS: Mutex<BTreeMap<...>>`全局锁来保证对IVC通道表的访问互斥。开发者在实现新命令时，若涉及共享资源，必须获取相应的锁（如`Mutex::lock()`），并在作用域结束前保持持有，利用RAII机制确保锁的自动释放。

## 示例实现：HC_VM_GET_INFO命令
以下为实现`HC_VM_GET_INFO`命令的步骤：

1.  在`axhvc::HyperCallCode`中添加新变体。
2.  在`hvc.rs`的`execute()`方法的`match`块中添加新分支：
    ```rust
    HyperCallCode::HC_VM_GET_INFO => {
        let info_type = self.args[0] as u32;
        let output_gpa_ptr = GuestPhysAddr::from_usize(self.args[1] as usize);
        // 根据info_type查询虚拟机元数据
        let vm_info = self.vm.get_metadata(info_type)?;
        // 将结果写回客户机指定的GPA
        self.vm.write_to_guest_of(output_gpa_ptr, &vm_info)?;
        Ok(0) // 成功返回0
    }
    ```
3.  确保`VMRef`类型提供了`get_metadata()`等安全查询方法。

## 安全最佳实践
- **输入验证**：始终验证所有来自客户机的输入，包括指针有效性、数值范围和数据结构完整性。
- **权限检查**：在执行敏感操作前，验证发起调用的VM是否有相应权限。
- **防止信息泄露**：避免将宿主系统的敏感信息（如物理地址、内部状态）直接暴露给客户机。输出的数据应经过脱敏或抽象化处理。
- **最小权限原则**：新命令应仅提供完成其功能所必需的最少接口和数据。
- **资源清理**：确保在错误路径上也能正确释放已分配的资源，防止泄漏。

## 客户机侧接口配合实现
客户机需要通过特定的CPU指令（如AArch64的`HVC #imm`）触发超调用。通常，这由客户机操作系统中的专用驱动或库函数封装。

客户机代码应：
1.  将命令码（`HC_VM_GET_INFO`）放入指定寄存器（如`X0`）。
2.  将参数按约定顺序填入后续寄存器（如`X1`, `X2`...）。
3.  执行`HVC`指令。
4.  检查返回值寄存器以判断调用是否成功。

## 通过串口日志验证调用流程
系统通过`info!`和`warn!`宏输出详细的运行时日志。开发者可通过连接串口控制台来监控超调用的执行情况。

验证步骤：
1.  在新命令的处理分支中添加`info!`日志，记录关键参数和执行点。
2.  启动虚拟机并触发客户机侧的超调用。
3.  观察串口输出，确认日志按预期打印，且无`Invalid hypercall code`或`Unsupported hypercall code`等错误。
4.  检查返回值和客户机侧接收到的数据是否符合预期。
